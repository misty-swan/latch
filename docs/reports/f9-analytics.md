# F9 Analytics諸量の集計の記録(02 §4 #35)

02 §4 #35(候補数・Jev実行回数・LATCH Score・YES/NO・Mutual Latch Rate(形式別)・チャット開始率の集計を出力する)の合格証拠として、集計のコマンド`pnpm analytics:report`(定義と数え方は09 §2)の実行結果を記録する。実装の担当(エージェント)が実行した(LAT-82)。

## 実行条件

| 項目 | 内容 |
|---|---|
| 実行日 | 2026-10-26 |
| 向け先 | 手元のD1(worker E2Eの状態`apps/worker/.wrangler/e2e-state`)。staging・本番には問い合わせていない(オーナーの決定 2026-10-26) |
| データ | worker E2E(`LATCH_E2E_PORT=9201 pnpm --filter worker test:e2e`・47件合格)が実際のAPIとパイプラインで作った意思・提案・回答・成立・チャット。LLMとEmbeddingはstub(決定的。LATCH Scoreはすべて0.900になる) |
| 命令 | `pnpm analytics:report --persist-to apps/worker/.wrangler/e2e-state --now 2026-11-03T12:00:00+09:00 --from 2026-10-26 --to 2026-10-26` |
| 集計の時刻 | E2Eのデータは実行の日に成立したため、チャット開始率を判定できるよう集計の時刻(`--now`)を成立から7日を過ぎた時点にした。`--now`を省くと、成立から7日たっていない成立は判定待ちとなり、チャット開始率は「—」になる |

## 読み方

- E2Eは試験ごとに意思を作っては期限切れや削除にするため、値は製品の利用の傾向を表さない。ここで確かめるのは、6つの数値が実際の記録から形式別に集計できることである。値の正しさは、行を配置した試験(`apps/worker/tests/analytics-report.test.ts`)が期待値と照らして確かめる
- 「候補数」と「評価の記録の呼び出し」の評価の回数は、毎分Cronが評価本体を直接呼ぶ評価と削除した意思の評価を含まない(09 §2のオーナー決定)。候補数の表の提示(1対1)は評価の時点で提示した件数で、この含まれない評価の分と、通知上限で保留した提案を後から提示した分を含まない。そのためMutual Latch Rateの提示した提案の件数より少ない
- 出力にはID・本文・表示名を含まない(08 §6)
