# F8a PWA 実機確認の手順書と記録

02 §4 の #32(PWAとして動作する)のうち、自動で証明できない「ホーム画面に追加・Web Push の受信・最小限のオフライン表示」を、オーナーが実際のスマホで確認するための手順書と記録の雛形。設計書 §4.3 に基づく。記録が揃うまで #32 は「実機確認待ち」と扱う。

確認の対象は iPhone の Safari と Android の Chrome。手元のパソコン(以下 PC)で LATCH を起動し、一時的なインターネット上のアドレス(HTTPS)をスマホから開く。

## 1. 準備(PC 側)

PC で LATCH のリポジトリのルートを開いたターミナルを使う。ターミナルは 2 つ必要(サーバー用とトンネル用)。

### 1-1. cloudflared を入れる(初回のみ)

cloudflared は、PC 内のサーバーを一時的に HTTPS のアドレスで公開する道具。Cloudflare のアカウントは要らない。

```bash
sudo pacman -S cloudflared
```

(Arch 系 Linux で cloudflared をインストールする。他の OS は Cloudflare 公式の案内に従う。)

### 1-2. 実機確認専用のビルドを作る

```bash
VITE_DEV_AUTH=1 pnpm --filter web build
```

(画面のプログラムを組み立て直す。`VITE_DEV_AUTH=1` を付けると、サインイン画面に「テストではじめる」が出る。)

重要: このビルドは実機確認のためだけのもの。本番用のビルドではない(Google や Apple のサインインは未接続のため、テスト用のサインインを使う)。確認が終わったら、本番の確認(Lighthouse など)の前に `pnpm --filter web build`(`VITE_DEV_AUTH` なし)で作り直す。

### 1-3. 設定ファイルを作り、Web Push を本物の送信にする

```bash
pnpm --filter worker exec node scripts/prepare-dev-vars.mjs
echo 'LATCH_PUSH_MODE=real' >> apps/worker/.dev.vars
```

(1 行目: テスト用の鍵などを入れた設定ファイル `apps/worker/.dev.vars` を作り直す。2 行目: その末尾に「通知を本物の送信先へ送る」指定を足す。)

- 設定ファイルを作り直すと中身が上書きされるため、必ず 1 行目の後に 2 行目を実行する。
- 通知の鍵(VAPID 鍵)は、コミット済みのテスト用の鍵がこの設定ファイルに入る。本番の鍵は F10 で発行する。
- `.dev.vars` は Git の管理外のファイル。コミットしない。
- 指定しない場合(既定の `stub`)は、通知を送った扱いにするだけで実際には送らないため、スマホには届かない。

### 1-4. データベースの準備とサーバーの起動(ターミナル 1)

```bash
pnpm --filter worker exec wrangler d1 migrations apply DB --local
pnpm --filter worker exec wrangler dev --local --test-scheduled --port 8787
```

(1 行目: 手元のデータベースを最新の形にする。2 行目: LATCH のサーバーを PC 内で起動する。動いている間はターミナルが占有される。`--test-scheduled` は、1 分ごとの定期処理を手動で動かせるようにする指定。)

別のプログラムが 8787 番を使っていて起動できないときは、8787 を空いている別の番号(例: 8791)に置き換え、以降の `8787` も同じ番号にする。他のプログラムは止めない。

起動できたかは、別のターミナルで次を実行して確かめる。

```bash
curl http://localhost:8787/healthz
```

(サーバーの生存確認。`{"status":"ok"}` と返れば成功。)

### 1-5. トンネルを開く(ターミナル 2)

```bash
cloudflared tunnel --url http://localhost:8787
```

(PC の 8787 番を、一時的な HTTPS のアドレスで公開する。)

表示される `https://xxxx.trycloudflare.com` の形のアドレスが、スマホで開くアドレス。このアドレスは起動のたびに変わる。

### 1-6. 終わったら片付ける

1. トンネルのターミナルで Ctrl+C を押してトンネルを閉じる(閉じるとスマホからは開けなくなる)。
2. サーバーのターミナルでも Ctrl+C を押す。
3. 通常の本番ビルドに戻す: `pnpm --filter web build`

## 2. 提案(Web Push の元になる通知)を作る手順

Web Push は「提案が届いた」ときに送られる。提案は、条件が合う 2 人の意思が預けられたときにサーバーが作る。そこで、スマホで 1 人目、PC のブラウザで 2 人目としてサインインし、同じ内容の意思を預ける。

### 2-1. スマホ(1 人目)

1. スマホのブラウザ(iPhone は Safari・Android は Chrome)で、1-5 のアドレスを開く。
2. 3-1 の項目 1 のとおりホーム画面に追加し、追加したアイコンから起動する(iPhone は、ホーム画面に追加したアプリからでないと Web Push を受け取れない。ブラウザで開いた画面とホーム画面のアプリでは保存先が別なので、サインインは必ずアイコンから起動した画面で行う)。
3. 「アカウントをお持ちの方」→「Googleで続ける」の順に押し、表示名(例: スマホ)を入れて「テストではじめる」を押す。
4. 登録の画面で表示名と生年月日(20 歳以上になる日付)を入れ、「次へ」→「同意して進む」。
5. 「閉じる」でホームへ。
6. 「ひとこと置く」→ 文章(例: 「週末にカレー屋巡りをしたい」)→「読み解く」→「預ける」。
7. 預けた画面で「通知を受け取る」を押し、許可の確認で「許可」を選ぶ。

### 2-2. PC(2 人目)

1. PC のブラウザで同じアドレス(または `http://localhost:8787`)を開き、2-1 の 3〜5 と同じ手順で別の表示名(例: PC)でサインインする。
2. 「ひとこと置く」で、2-1 の 6 と完全に同じ文章を入れて「読み解く」→「預ける」。地域や日時は指定しない。

### 2-3. 提案が作られるまで

- 預けたあとの処理(読み解き結果の登録・相手探し・提案づくり)は、サーバーが順に自動で行う。通常は数秒〜1 分ほど。
- 提案が来ない、または通知が来ないときは、次の定期処理を手動で動かす(取りこぼしの回収と、Web Push の再送を行う)。

```bash
curl http://localhost:8787/__scheduled
```

(1 分ごとの定期処理を今すぐ 1 回動かす。`200` が返れば成功。数秒待ってからスマホを見る。)

- それでも提案が来ないときの原因の調べ方: PC のブラウザのアドレス欄に `http://localhost:8787/v1/dev/match-events` を入れても認証が要るため開けない。調べる場合は担当のエンジニアに依頼する。同じ文章で合わないときは、文章を変えて 2 人とも預け直す(古い意思は、ホームの一覧から取り下げる)。
- この「同じ文章を 2 人が預ける」手順は、手順書の作成時点では実機で通しの確認をしていない。合わなかった場合は、その旨を記録欄の「メモ」へ書く。

## 3. 確認項目と記録

端末ごとに次の表を埋める。結果は「OK」「NG」「未確認」のいずれかと、日付(年月日)を書く。NG のときはメモ欄に状況(表示された文言・画面の様子)を書く。

### 3-1. 項目の手順

| 番号 | 項目 | 手順と期待する結果 |
|---|---|---|
| 1 | ホーム画面に追加 | iPhone Safari: 共有ボタン → 「ホーム画面に追加」。Android Chrome: メニュー(︙)→「ホーム画面に追加」または「アプリをインストール」。ホーム画面に LATCH のアイコンが現れ、アイコンの絵が欠けず表示される |
| 2 | 枠なしで起動 | 追加したアイコンから起動する。ブラウザのアドレス欄やタブが無く、アプリだけの画面(standalone)で開く |
| 3 | 通知の許可 | 2-1 の 7 のとおり「通知を受け取る」を押し、許可の確認が出て「許可」を選べる。許可後も画面が崩れない |
| 4 | Web Push の受信と汎用文 | 2 の手順で提案を作る。スマホに通知が届く。本文は「提案が届いています。詳細はアプリでご確認ください。」という固定の汎用文で、相手の名前や意思の内容が書かれていない |
| 5 | タップで一覧が開く | 届いた通知をタップする。LATCH が開き、アプリ内通知の一覧(画面名「お知らせ」)が表示され、提案の行がある |
| 6 | 電波を切って開き直し | 機内モードにするか Wi-Fi とモバイル通信を切り、アプリを完全に閉じてから開き直す。ホームに「オフラインです。最後に確かめた内容を表示しています。」の帯が出て、最後に表示した一覧が見える。通信を戻すと帯が消える |

| 「インストール可能」の表示 | OK(アドレス欄にインストールのアイコンが出る。この版の Manifest の画面には「Installability」の欄が無く、「Errors and warnings」に次の4件が出た) |
| 画面の写し | なし |

「Errors and warnings」の4件(いずれもインストールは妨げない。issue #6):

- `screenshots` が無いため、画面写真つきのインストール画面が出ない(デスクトップ用の wide・モバイル用の各1件)
- `Icon http://localhost:8787/icon.svg failed to load`(ブラウザの `<img>` では読み込める。原因は未確認)
