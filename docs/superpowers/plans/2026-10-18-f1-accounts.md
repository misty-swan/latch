# F1 アカウント実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** F1「アカウント」— auth 3API(token/refresh/logout)・users登録・me・アイコン(R2)・テスト鍵起動ガード・認証E2Eを実装する(12 §2のF1行)。

**Architecture:** F0の単一Worker(Hono)の上に、認証モジュール(JWT=HS256 1時間・リフレッシュ回転式30日・KV失効リスト)とユーザー/アイコンのルートを追加する。IdP検証はjose。テスト用IdP鍵(JWKS)を環境変数で注入できるようにし、prod環境で残存していれば起動ガードが拒否する(10 §2)。E2EはブラウザUIなし・PlaywrightのAPIテスト機能でAPIフローを通し検証する(オーナー承認済み・画面はF2')。

**Tech Stack:** TypeScript(strict)・Hono・jose・ulid・Zod(@hono/zod-validatorは使わずZodを手動適用 — リクエスト検証の共有スキーマはpackages/shared)、Drizzle(D1)・KV(REVOCATION_KV)・R2(ICONS)・vitest-pool-workers・Playwright(@playwright/test、APIのみでブラウザ不要)。

**Spec:** `docs/12-development-roadmap.md` §2(F1の行)・`docs/05-data-model-api.md` §2.2/§3.1/§3.2/§3.3・`docs/04-system-architecture.md` §4(認証・セッション)/§3.1(技術スタック)・`docs/08-privacy-safety.md`(アイコン検証・ログ規律)・`docs/10-test-env-nfr.md` §2(テスト鍵・起動ガード)。

## Review Focus

1. **窃取された旧リフレッシュトークンの再利用** — 猶予窓外の再提示は族revoked+401。猶予内の再提示は1回のみ現行トークンを返し、2回目は拒否 → Task 6のテスト
2. **期限切れリフレッシュトークン(30日経過)** — 401 TOKEN_EXPIRED(族失効はしない・UNAUTHORIZEDと切り分ける) → Task 6・8のテスト
3. **年齢境界** — 18歳の誕生日当日は登録可・前日は422 UNDER_AGE・2/29生まれは平年に3/1到達で18歳(カレンダー比較方式・選択はコードコメントに明記) → Task 9の単体テスト
4. **改ざんIdPトークン**(未知kid・期限切れ・iss/aud不一致) — 401 UNAUTHORIZEDで登録・トークン発行不可 → Task 5・11のテスト
5. **不正アイコン**(1MB超過・magic bytes不一致・拡張子偽装)と**存在しない/削除済みユーザーのアイコンGET** — 400 VALIDATION_FAILED / 404 → Task 10のテスト

### Task 6: リフレッシュトークン(回転・猶予・再利用検出)

**Files:**
- Create: `apps/worker/src/auth/refresh.ts`
- Create: `apps/worker/src/auth/refresh.test.ts`(統合・env.DB/env.REVOCATION_KV使用)

**Interfaces:**
- Consumes: `Env`(Task 3)・`Clock`・`refreshFamilies` スキーマ(Task 1)
- Produces:
  - `const REFRESH_TTL_DAYS = 30` / `const GRACE_WINDOW_SECONDS = 120`
  - `const REFRESH_GRACE_KV_PREFIX = "rfg:"`
  - `sha256Hex(s: string): Promise<string>`(crypto.subtle)
  - `generateRefreshToken(): { token: string; hash: string }`(32バイト乱数→base64url)
  - `createRefreshFamily(env: Env, clock: Clock, userId: string): Promise<{ token: string; familyId: string }>`(INSERT・expires=now+30日)
  - `type RotateResult = { ok: true; userId: string; refreshToken: string } | { ok: false; code: "UNAUTHORIZED" | "TOKEN_EXPIRED" }`
  - `rotateRefreshToken(env: Env, clock: Clock, presentedToken: string): Promise<RotateResult>`
  - `revokeFamilyByToken(env: Env, token: string): Promise<void>`(current_hash一致する族をrevoked。logout用)

`rotateRefreshToken` の動作(設計の正):
1. `UPDATE refresh_families SET current_hash=:新ハッシュ, previous_hash=:提示ハッシュ, rotated_at=:now, expires_at=:now+30日 WHERE current_hash=:提示ハッシュ AND status='active' AND expires_at > :now RETURNING user_id` が成功 → KV `rfg:{提示ハッシュ}` に新トークンをTTL=GRACE_WINDOW_SECONDSで置き `{ok:true}`(Drizzleの `.returning()` で更新成功を確認)
2. 0行なら `SELECT * WHERE current_hash=:提示ハッシュ` で行を確認: status≠active → UNAUTHORIZED / expires_at≤now → TOKEN_EXPIRED
3. 行が無ければ猶予判定: `KV get rfg:{提示ハッシュ}` に値があれば `{ok:true; refreshToken=KV値}`(=回転時に保存した現行トークンの再返却・04 §4の猶予)。返却後にKVキーを削除して使い切りとする
4. 3でKVに無く、`SELECT` で `previous_hash=:提示ハッシュ AND status='active'` の行が見つかれば**再利用検出**: その族を `UPDATE status='revoked'` して UNAUTHORIZED
5. いずれにも該当しない未知トークン → UNAUTHORIZED(族を特定できないため失効対象なし)
