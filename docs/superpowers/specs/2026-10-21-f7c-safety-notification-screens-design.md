## 0. 前提と範囲

### 0.1 ゲート

- **#16の画面部分**: 提案がアプリ内通知(画面名「お知らせ」)に届き、そこから提案を開いて回答できること。web E2E(§5.2)で証明する。実機ブラウザでのWeb Pushの受信確認はF8(#32)
- **#31**: 規約の規制領域禁止の明記と法務確認の完了。人間領域(プロダクトオーナー)のため、F7cは利用規約・プライバシーポリシーの草案をページに置くところまでを担う。法務確認の実施と記録はオーナーが行う(§0.2の1)
- APIは追加しない(F7a・F7bで完成済み)。例外はService Workerのプッシュ処理(§3)

### 0.2 オーナー合意(2026-10-21)

| # | 論点 | 合意 |
|---|---|---|
| 1 | 利用規約・プライバシーポリシーの文面 | 草案をF7cで書いてページに置く。08 §10の必須事項を含め、冒頭に「法務確認前の草案」の印を付ける。法務確認(#31の証明)はオーナーが後で行う |
| 2 | 成立後の通報で相手と発言をどう選ぶか | 発言の通報はチャットのメッセージ(相手の発言)の操作から始め、発言と相手を自動で決める(通報画面は理由・くわしくだけ)。チャットの「…」からの通報はプロフィール・アイコンを選ばせ、グループでは相手を選ぶ欄を加える |
| 3 | グループのチャットに「ブロックする」を置くか | 置く(prototypeは1対1のみ)。グループでは相手を選んでからブロックし、確認シートで「このグループから抜ける」ことを伝える |

不採用の案: (1) 枠だけ作り文面を後で差し込む案・F10へ回す案は、法務確認に対象の文書が先に要るため採らない。(2) 通報画面で相手の発言一覧から選ばせる案は操作が増え、直近の発言を自動で対象にする案は誤った発言を記録し得るため採らない。(3) グループでブロックを置かない案は、抜けても同じ相手との提案が届き得るため採らない。

### 0.3 F7cで行わないこと

- 退会(DELETE /v1/users/meが後続フェーズ)・ヘルプ/お問い合わせ(行き先なし)。「自分」画面にこの2行を出さない
- 意思ごとの通知設定(notification_level)の切り替え。意思の詳細画面とともにF8で扱う
- オフライン表示・Service Workerのキャッシュ方針(F8)・Web Pushの実機受信確認(F8)・本番VAPID鍵(F10)
- 法務確認の実施(オーナー)

## 1. 画面

### 1.1 URL

| URL | 画面(ボード) | 認証 |
|---|---|---|
| `/notices` | お知らせ一覧(Notices / NoticesEmpty) | 登録済み |
| `/me` | 自分(Me) | 登録済み |
| `/me/profile` | プロフィール編集(Profile) | 登録済み |
| `/settings` | 通知と表示(Settings・PushOff) | 登録済み |
| `/settings/blocked` | ブロックしたユーザー(Settings?section=blocked) | 登録済み |
| `/latches/:id/report` | 通報(Report)。`?message=<message_id>&user=<user_id>`でメッセージの通報 | 登録済み |
| `/terms`・`/privacy` | 利用規約・プライバシーポリシー(草案) | 不要(サインイン前から開ける) |

`/consent?view=1`(外部送信と同意の閲覧専用)は既存のConsent画面に閲覧モードを足して「自分」から開く。

### 1.2 既存画面への入口

- **ホーム・つながり一覧の右上**: ベル(未読があれば点・aria-labelに「(未読N件)」)→`/notices`、アイコン→`/me`(現状は飾りの表示)
- **提案画面の右上「…」**: シート「この提案について」→「この提案を通報する」→`/latches/:id/report`
- **チャットの操作メニュー**: 「通報する」→`/latches/:id/report`/「ブロックする」→ブロックの確認シート(§1.8)
- **チャットのメッセージ**: 相手の発言の長押し(とキーボード操作できる発言横のメニュー)→「このメッセージを通報する」→`/latches/:id/report?message=…&user=…`。自分の発言には出さない
- **預けた画面**: 「通知を受け取る/あとで」を実際の許可と購読につなぐ(§3)
- **読み解き確認**: お酒を含む機会で満20歳未満なら、AlcoholRestrictedボードどおり「預ける」を止めて説明を出す(§1.9)
- **サインイン画面・外部送信と同意**: 「利用規約」「プライバシーポリシー」のリンクを`/terms`・`/privacy`へ

### 1.3 お知らせ一覧(`/notices`)

- 見出し「お知らせ」・戻る→ホーム。`GET /v1/notifications`を20件ずつ、末尾で続きを読み込む
- 行(prototypeの`screens.notices`どおり。未読は`is-unread`):
  - proposal: 「提案が届いています」+回答期限(提示中のとき)+経過時間 →`/latches/:id`(状態で画面が切り替わる既存のLatchScreen)
  - matched: 「{表示名を・でつないだもの}さんとつながりました」(終了したつながりは表示名を出さず「つながりました」)→`/latches/:id/chat`
  - closed: 「この提案は成立しませんでした」(押せない行)
  - intent_expired: 「預けていた意思の期限が切れました」+本文1行+[もう一度預ける](本文を預ける画面の入力に入れて`/compose`を開く)
- 空: 「お知らせは、まだありません。」「提案が届いたときや、期限が来たときに、ここでお伝えします。」
- 1頁目を読み込めたら、先頭(最新)のidで`POST /v1/notifications/read`を送り、未読数の問い合わせを取り直す

### 1.4 自分(`/me`)

- 上段: アイコン・表示名・ひとこと(未設定は「ひとことは未設定です」)・「このプロフィールは、つながった相手にだけ表示されます。」・[プロフィールを編集]
- 設定: 通知と表示 / ブロックしたユーザー / 外部送信と同意(閲覧専用)
- そのほか: 利用規約 / プライバシーポリシー / ログアウト(`POST /v1/auth/logout`→保存しているトークンを消す→ようこそ)

### 1.5 プロフィール編集(`/me/profile`)

- アイコン: [画像を選ぶ](PNG・JPEG・WebP・1MBまで。外れたら送る前に画面で止める)→`POST /v1/users/me/icon`/[既定のアイコンに戻す]→`DELETE /v1/users/me/icon`
- 表示名(1〜40字・カウンター)・ひとこと(任意・0〜200字・カウンター)。[保存]→`PATCH /v1/users/me`(変わった欄だけ)→`/me`。[やめる]→`/me`

### 1.6 通知と表示(`/settings`)・ブロックしたユーザー(`/settings/blocked`)

- プッシュ通知のスイッチ(説明「提案と、つながったときだけ届きます。本文に内容は表示されません。」)。動きは§3
- 表示: 端末の設定に合わせる / 昼(明るい紙)/ 夜(暗い紙)(既存のtheme.tsxにつなぐ)
- 「意思ごとのお知らせは、それぞれの意思の画面で切り替えられます。」はF8で意思の画面ができるまで出さない
- ブロックしたユーザー: `GET /v1/blocks`の各行(アイコン・表示名・「M月D日にブロック」・[解除])。解除→`DELETE /v1/users/{user_id}/block`→取り直し。注記「解除すると、また提案が届くことがあります。以前に提案された相手との提案は、解除後も届きません。」。0件は「ブロックしたユーザーはいません。」

### 1.7 通報(`/latches/:id/report`)

- 冒頭「通報したことは、相手には通知されません。運営が内容を確かめ、5営業日以内に対応します。」・[やめる]で元の画面へ
- 対象の欄は入口で変わる:
  - 提案(LATCHが提案段階): 対象の欄を出さない(target=proposal・相手は指定しない)
  - チャットの「…」: 「プロフィール(表示名・ひとこと)」「アイコン」(target=profile|icon)。グループは「相手」(自分以外の参加者の表示名のラジオ)を加える
  - メッセージ(`?message=&user=`): 対象・相手の欄を出さず、通報する発言の本文を引用して見せる(target=message)
- 理由: スパム・勧誘=spam / 嫌がらせ=harassment / 不適切な内容=inappropriate / その他=other。くわしく(任意・500字)
- [通報する]は必須の選択が揃うまで押せない→`POST /v1/reports`→完了の一文「通報を受け付けました。」を出して元の画面へ戻る

### 1.8 ブロック(チャットの操作メニュー内のシート)

- 1対1(prototypeの`screens.block`): 「{表示名}さんを、ブロックしますか。」・「このつながりのチャットは、読み取り専用になります。」「今後、この相手との提案は届きません。」「ブロックしたことは、相手に通知されません。」・[ブロックする](危険色)/[やめる]
- グループ: 先に相手を選び、確認の説明を「このグループから抜けます。チャットは読み取り専用になります。」「今後、この相手との提案は届きません。」「ブロックしたことは、相手に通知されません。」とする
- 実行→`POST /v1/users/{user_id}/block`→LATCH・つながり一覧・お知らせを取り直す(チャットは読み取り専用の表示へ)

### 1.9 お酒と年齢(読み解き確認)

- お酒を含む機会Intentで本人が満20歳未満のとき、AlcoholRestrictedボードどおり「お酒を含む機会は、20歳以上の方が預けられます。」「「お酒」をオフにすると、このまま預けられます。」を出し、[預ける]を押せなくする
- 満年齢は`GET /v1/users/me`の生年月日から日本時間の誕生日で1つ進む規則で計算する(08 §8・サーバーと同じ規則)。サーバーの422 ALCOHOL_RESTRICTEDも同じ表示で受ける

### 1.10 規約ページ(`/terms`・`/privacy`)

- 冒頭に「この文書は法務確認前の草案です。」の印。戻る→直前の画面(無ければようこそ)
- 利用規約の草案に含める: サービスの目的・18歳以上・転職(職業安定法)・売買(古物営業法等)・交際/出会い目的と営業目的の使用の禁止・虚偽通報の反復の禁止・ユーザーアイコンの権利義務・退会後のメッセージの保持・地名データのクレジット(位置参照情報 CC BY 2.0 JP・駅データ CC BY 4.0)
- プライバシーポリシーの草案に含める: 取得する情報と利用目的・外部AI事業者への送信(委託か第三者提供かの区分は法務確認の論点として明示)・成立前の非開示・バックアップ7日の保持・退会と削除・開示等請求の窓口(窓口の連絡先は法務確認時に確定と明示)
- 本文は画面のコードに置く(1ファイル1文書)。法務確認の対象は11 §1のチェックリストに紐づける

## 2. データの取得と更新

- お知らせの未読数: `GET /v1/notifications`(1頁目)の`unread_count`。ホーム・つながり一覧の表示時・アプリ復帰時・60秒ごとに取り直す(TanStack Queryの共有キー)
- 自分: `GET /v1/users/me`(共有キー)。プロフィール保存・アイコン変更の後に取り直す
- ブロック・通報の後は、そのLATCH・つながり一覧・お知らせのキーを無効化する

## 3. プッシュ通知の許可と受信

### 3.1 許可と購読

- 預けた画面の[通知を受け取る]・設定のスイッチのオン: `Notification.requestPermission()`→許可なら`GET /v1/push/vapid-public-key`→`pushManager.subscribe({userVisibleOnly: true, applicationServerKey})`→`POST /v1/push-subscriptions`
- [あとで]は何もしない(その端末で許可が未決のあいだ、預けた画面でまた聞く)
- スイッチのオフ: `subscription.unsubscribe()`→`DELETE /v1/push-subscriptions`
- スイッチの表示: 購読あり=オン。ブラウザが拒否済み=押せない+PushOffの説明「ブラウザの設定で通知がオフになっています。提案は、アプリ内のお知らせでお伝えします。」(ホームの帯も同じ条件・ボードどおり)。プッシュ非対応のブラウザ=押せない+アプリ内のお知らせで届く旨
- 購読の登録が失敗したらスイッチをオフに戻し、アプリ内のお知らせで届く旨を出す

### 3.2 Service Worker(案A: importScripts)

- `vite-plugin-pwa`の自動生成(generateSW)は変えず、`workbox.importScripts`でプッシュ処理だけの小さなファイル(`public/push-sw.js`)を読み込ませる
- `push`: ペイロード`{type, body}`の`body`をそのまま通知の本文に出す(題名「LATCH」・IDも内容も無い・08 §3)。ペイロードが読めなければ既定の汎用文
- `notificationclick`: 開いているLATCHのタブがあればそこで`/notices`へ、無ければ新しく開く
- 不採用: injectManifestへの切り替え(F7cの範囲を超えてキャッシュ処理を自前で持つことになる)

## 4. 失敗時の扱い

- 通報・ブロック・解除・プロフィール保存が失敗したら画面に留まり、一文の注意「送れませんでした。時間をおいて、もう一度お試しください。」を出して再操作できるようにする
- 通報・ブロックの404は理由を区別せず「この操作はできませんでした。」とする(相手の状態を推測させない・08 §8)
- プロフィールの400(字数等)は該当欄の下に出す

## 5. 試験

### 5.1 単体・結合(vitest)

- 各画面の表示(ボードの文言)・入口・押したときのAPI呼び出し・失敗表示
- 満年齢の計算(日本時間の誕生日の境界)・プッシュ購読の手順(許可・拒否・非対応・登録失敗)を関数単位で
- Service Workerのプッシュ処理は通知の題名・本文・押したときの遷移先を関数単位で

### 5.2 web E2E(Playwright chromium・`notices-flow.spec.ts`)

1. **#16の画面部分**: 2人が一致する意思を預ける→提案が届く→ホームのベルに点→お知らせ一覧→提案を開いて[参加する]→相手も参加して成立→お知らせに「つながりました」→押すとチャット・既読で点が消える
2. 通報: 提案の「…」から通報、チャットの相手の発言から通報し、dev観測API(GET /v1/dev/reports)で記録を確かめる
3. ブロック: 1対1のチャットでブロック→ブロックした側はブロックしたユーザーに相手が出る・相手側は「このつながりは終了しました」と読み取り専用
プッシュの購読はE2Eに含めない。ChromiumのpushManager.subscribeは実際のプッシュサービスへ通信し、CIの環境で結果が揺れるため。購読の手順は§5.1の単体試験(pushManagerを差し替える)で担保し、実際の購読と受信はF8(#32)の実機確認で行う
