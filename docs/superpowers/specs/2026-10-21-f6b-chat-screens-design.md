### 0.2 オーナー合意(2026-10-21)

| # | 論点 | 合意 |
|---|---|---|
| 1 | 「表示から消す」の説明文(01 §10「一覧の操作ラベルにその違いを反映する」) | 状態で文言を分ける。続いているつながり=「このつながりを終えて、自分の一覧から消します。相手の側には履歴が残ります。」/終了後=「自分の一覧から消します。相手の側には残ります。」(prototypeの文言) |
| 2 | 「参加を取り消す」「表示から消す」の確認 | 元に戻せないため、シートの中で一段の確認を挟む(prototypeは即実行) |
| 3 | 1通の上限字数(prototype 1,000字 / 05 §2.2 2,000字の食い違い) | APIの2,000字に揃える。API・05は変えない |
| 4 | F6bで作らないもの・終了したつながりの名前 | §0.3のとおり。名前はprototypeどおり、成立後のcancelledは「つながっていた相手」、completedは実名 |
| 5 | 通信の組み立て方 | 案A: 受信はWebSocket、送信はREST(§2) |

案B(送受信ともWebSocket)は不採用。理由: 送信の成否を時間切れで判定する仕組みが要り、失敗表示と再送が複雑になる。RESTの応答なら成否が1つの応答で決まり、サーバー側はどちらの経路でも同じDOの1か所で保存→全員へ配信するため体感の速さも変わらない。定期取得だけの案はチャットのリアルタイム化(04 §4・確定裁定)に反するため不採用。

## 1. 画面

### 1.1 URL

| URL | 用途 |
|---|---|
| `/connections` | つながり一覧(Connections / ConnectionsEmpty) |
| `/latches/:id/chat` | チャット(Chat / ChatGroup / ChatEnded / ChatMenu / SendFailed) |

どちらも登録済みユーザーのみ(既存のRequireAuthで保護)。

### 1.2 つながり一覧(`/connections`)

- 見出し「つながり」・注記「お互いが参加して、つながった相手です。」
- `GET /v1/latches?type=matched`を「つながっている」(status=matched)と「終了」(completed・成立後のcancelled)の2区分に分けて並べる(区分の中はAPIの順)。区分が空なら見出しごと出さない
- 各行(`.conn`・終了は`is-ended`): アイコン・名前(§1.4)・「主題·形式」(終了は「·終了」)・最終メッセージ(`last_message.body`・無ければ「最初のひとことを送ってみましょう」)・経過時刻(最終メッセージ、無ければ`matched_at`から。「N分前」等はprototypeの`ago`の表記に従う)・未読数(`unread_count`が1以上のとき`.unread`)。押すと`/latches/:id/chat`
- 1頁50件。`next_cursor`があれば末尾に[さらに表示]で続きを読み込む
- 0件ならConnectionsEmpty(終わった半円・「まだ、つながりはありません。」・「提案にお互いが参加すると、ここに並びます。それまでは、預けて待つだけです。」)
- 下部タブ(預けている/置く/つながり)を置き、「つながり」を現在の頁とする

### 1.3 チャット(`/latches/:id/chat`)

- 見出し: アイコン(グループは並べる)・名前(§1.4)・「主題·形式」(終了後は「·終了」)。左上は戻る(`/connections`)・右上「…」(このつながりについて)でメニュー
- 冒頭(`.chat__origin`): 半円(続いている=`is-latched`・終了=`is-ended`)・「M月D日 HH:MM につながりました」(`matched_at`)・「主題·N人」(機会は場所があれば「·場所」)。主題が無ければ主題の部分を省く
- 本文: 日付が変わるところに区切り(今日なら「今日」、それ以外は「M月D日」)・自分の発言は右(`msg--mine`)・相手は左(`msg--theirs`)・グループの相手の発言には送り主名(`msg__who`)・時刻(HH:MM)。メッセージが0件なら「最初のひとことは、短くて大丈夫です。」
- 開いたときは最下部を表示する。上端まで戻ると古い履歴を50件ずつ読み込む(読み込み後も見ていた位置を保つ)
- 入力欄(`.composer`): 2,000字まで(§0.2の3)・前後の空白を除いて空なら[送る]を押せない・高さは内容に合わせて最大140px・Ctrl/⌘+Enterで送信(prototypeどおり)。送信後は入力欄を空にする
- 終了後(completed・成立後のcancelled)は入力欄の代わりに帯「このつながりは終了しました」(`.ended-bar`)
- status=matched以外で成立前・成立せず閉じたLATCH(履歴APIが400 invalid_status)・404は、`/latches/:id`へ置き換え遷移する(F4cの状態の切り替えに任せる)

### 1.4 名前とアイコンの出し方

| 状態 | 名前 | アイコン |
|---|---|---|
| matched・completed(1対1) | 相手の表示名 | 相手のアイコン(`has_icon`がfalseなら無地) |
| matched・completed(グループ) | 相手全員の表示名を「・」でつなぐ | 並べる(一覧は先頭2人) |
| 成立後のcancelled | 「つながっていた相手」 | 無地(`avatar--gone`) |

グループで途中で抜けた人(membersに居ない・自分でもない)の過去の発言は、送り主名を「つながっていた相手」とする。アイコンの取得はF4cと同じ`GET /v1/users/{user_id}/icon`。

### 1.5 送信失敗(SendFailed)

- 通信失敗・500: 自分の吹き出しを`is-failed`にし「送信できませんでした [もう一度送る]」。[もう一度送る]は同じ`client_id`で再送する(§2.3)
- 400 read_only・404: 失敗表示にせず、LATCHの取得をやり直して終了の表示(§1.3)・`/latches/:id`への遷移へ切り替える。入力していた本文の吹き出しは消す
- 400 invalid_message: 画面側の制限(§1.3)で通常は起きない。起きた場合は失敗表示と同じ扱い

### 1.6 操作メニュー(ChatMenu・シート)

| 状態 | 項目(説明文) |
|---|---|
| matched・1対1 | 参加を取り消す(このつながりを終えます。チャットはお互いに読み取り専用になります。)/ 表示から消す(このつながりを終えて、自分の一覧から消します。相手の側には履歴が残ります。) |
| matched・グループ | 参加を取り消す(このつながりから抜けます。)/ 表示から消す(このつながりから抜けて、自分の一覧から消します。相手の側には履歴が残ります。) |
| completed・成立後のcancelled | 表示から消す(自分の一覧から消します。相手の側には残ります。) |

- 下に[閉じる]
- 項目を押すと同じシートの中で確認に切り替える: 「参加を取り消しますか。元には戻せません。」[取り消す]/[やめる]、「表示から消しますか。元には戻せません。」[消す]/[やめる](§0.2の2)。送信中はボタンを押せなくする
- 参加を取り消す=`POST /v1/latches/{id}/leave`。成功後: 1対1・下限割れのグループはその場で読み取り専用の表示へ、本人だけが抜けたグループ(以後404)は`/connections`へ。トースト「参加を取り消しました。」
- 表示から消す=`DELETE /v1/latches/{id}`。成功後は`/connections`へ戻り、トースト「一覧から消しました。」
- 失敗(400・404・通信失敗)は、LATCHを取り直して正しい表示にし、短い一文(「この操作は、いまはできません。」)を出す

### 1.7 既存画面の変更

- つながりました画面(Matched): 下部に[メッセージを送る](主・`/latches/:id/chat`へ)を追加し、「あとで」は控えめなボタンとして残す(prototypeどおり)
- Homeの下部タブ「つながり」を`/connections`へのリンクにする(現在は表示のみ)
- `/latches/:id`の「このつながりは終了しました」表示(completed・成立後のcancelled)に、履歴を読むための[チャットを見る](`/latches/:id/chat`)を追加する

## 2. データの流れと通信(案A)

### 2.1 取得

| 対象 | API | 備考 |
|---|---|---|
| つながり一覧 | `GET /v1/latches?type=matched&limit=50&cursor=…` | TanStack Queryの頁送り |
| チャットの見出し・状態 | `GET /v1/latches/{id}` | F4cの`useLatchQuery`を再利用 |
| 自分のユーザーID | `GET /v1/users/me` | 1回取得して使い回す。自分の発言の見分けに使う(`client_id`の有無では見分けない: 別の端末から自分が送った分が相手の発言に見えるため) |
| 履歴 | `GET /v1/latches/{id}/messages?before=…` | 新しい50件から、上へ戻るたびに`next_before`で古い50件。TanStack Queryの頁送り |

### 2.2 受信(WebSocket)

- チャット画面を開いていて、LATCHがmatchedの間だけ接続する。接続のたびに`POST /v1/ws-ticket`でチケットを取り直す(1回限り・60秒)
- 届いた`message`は履歴の末尾へ足す(同じIDは重ねない)。表示中なら既読を送る(§2.4)
- `closed`が届いたらLATCHを取り直し、読み取り専用の表示へ切り替える(接続は閉じたまま再接続しない)
- 切れたら待ち時間を倍にしながら再接続する(1秒→2秒→4秒…最大30秒・接続に成功したら1秒へ戻す)。再接続の成功時と画面に戻ったとき(window focus)に最新の頁を取り直し、切れていた間の取りこぼしを埋める
- チケットの取得が404・400(抜けた・終了した)なら再接続をやめ、LATCHを取り直す。401(アクセストークンの期限)は既存の`apiFetch`の更新処理に任せる
- 25秒ごとにpingを送る(サーバーはDOの自動応答でpongを返す)
- 画面を離れたら接続を閉じ、再接続・pingを止める

### 2.3 送信(REST)

- [送る]で端末が作る`client_id`(1〜64字の`[A-Za-z0-9_-]`)を付けて`POST /v1/latches/{id}/messages`
- 応答を待つ間は自分の吹き出しを「送信中」(薄い表示)で先に出す。201の応答で本物に置き換える。WebSocketで同じメッセージが先に・後に届いても、IDと`client_id`で重ねない
- 失敗の扱いは§1.5。再送は同じ`client_id`で行い、サーバーの冪等(F6a §2.1)により実は保存されていた場合も二重にならない
- 送信中・失敗中の吹き出しは画面の中だけに持ち、画面を離れると消える(端末に保存しない)

### 2.4 既読

- チャットを開いたとき・新しいメッセージを表示したとき、表示中の最新のメッセージIDで`POST /v1/latches/{id}/read`を送る(同じIDを続けて送らない)。終了後も送る(F6aで終了後の既読は可)
- 前にだけ進む規則はサーバーに任せる。一覧へ戻ると一覧を取り直し、未読数が更新される

### 2.5 操作の後の取り直し

`leave`・`DELETE`・送信の成功後は、つながり一覧と当該LATCHの取得結果を無効化して取り直す(F4cの`applyResult`と同じ考え方)。

## 5. 試験

### 5.1 単体・画面試験(毎コミット・vitest)

- `socket.ts`: 偽のWebSocketで、接続・`message`の受け渡し・`closed`で再接続しないこと・再接続の待ち時間の伸び方と成功後の戻り・pingの間隔・チケット取得の404/400で再接続をやめること(偽の時計で早送りする)
- 一覧: 2区分の振り分け・名前の出し方(§1.4の各行)・最終メッセージ/未読/経過時刻・空の状態・[さらに表示]
- チャット: 日付の区切り・自分/相手の吹き出し・グループの送り主名(抜けた人は「つながっていた相手」)・古い履歴の読み込み・届いたメッセージの追加と重複の排除・既読の送信(同じIDを続けて送らない)・成立前/404の置き換え遷移
- 送信: 送信中の表示→確定・失敗表示と同じ`client_id`での再送・read_only/404で取り直し・2,000字と空白の制限・Ctrl/⌘+Enter
- メニュー: 状態ごとの項目と文言(1対1/グループ/終了後)・確認の一段・取り消し/消すの後の表示とトースト・失敗時の取り直し
- 既存画面: つながりました画面の[メッセージを送る]・Homeのタブ・終了表示の[チャットを見る]

### 5.2 web E2E(02の番号は持たない)

`apps/web/e2e/chat-flow.spec.ts`を新設し、2つのブラウザ(Playwrightのbrowser context)で2人のユーザーを演じる。

1. F4cの補助関数で2人を成立させる。Aがつながりました画面の[メッセージを送る]でチャットへ進む
2. Aが送信 → Bのチャット画面に再読み込みなしで届く(WebSocket)。Bが返信 → Aに届く
3. Bのつながり一覧に最終メッセージと未読が出て、チャットを開いて戻ると未読が消える
4. Aがメニューから「参加を取り消す」(確認を経る)→ Aは読み取り専用の表示。Bの画面は`closed`で「このつながりは終了しました」に切り替わり入力欄が消える。Bの一覧では「終了」区分に「つながっていた相手」として出る
5. Bが「表示から消す」(確認を経る)→ Bの一覧から消える

送信失敗の表示は通信を意図的に遮断する必要があるため、E2Eではなく§5.1の画面試験で証明する。
