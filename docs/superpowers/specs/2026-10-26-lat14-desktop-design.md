# PC向けの画面(LAT-14) 設計書

- 作成日: 2026-10-26
- 対象: LAT-14(PCのブラウザで開くとスマホの画面が横いっぱいに伸びる)
- 正本: `prototype/project/Desktop.dc.html`(PCの基準のボード)・`prototype/README.md`・`prototype/app/shell.css`(試作の外枠。820px以下で端末の枠を外す)/ docs/04 §3.2 / docs/10 §4 / docs/12 §2 の決定記録(不具合の修正工程(第2回))の4「幅を絞るだけの手当てはしない。PC向けの画面を作る」
- 本書の位置づけ: 試作から読み取れない見た目の判断をオーナーが承認したPC向けのデザイン(2026-10-26・下記§3のキャンバス)に沿って、apps/webでの作り方を記録する

## 0. 前提

- PCで開く相手(ポートフォリオとしてURLを受け取った面接の相手)に、スマホの画面を横に引き伸ばしたものではなく、PCの幅を生かした画面を見せる
- スマホの幅の見た目と挙動は変えない。`apps/web/src/styles/latch.css`(prototypeからの不改変コピー)は編集せず、足すスタイルは `apps/web/src/styles/desktop.css` に置く
- 試作のPCのボードは「預けている+提案」の1枚(1440×900・左のナビ256px/中央の本文/右に夜の配色の提案の部屋520px)だけ。ほかの画面は、試作の部品(`latch.css`)だけで組んだPC向けのデザインをキャンバスに描き、オーナーの承認を得た(§3)

## 1. 幅の区切り

| 画面の幅 | 見せ方 |
|---|---|
| 820px以下 | 今と全く同じ(外枠の要素は `display: contents` で無いものとして扱う) |
| 821px以上 | 画面をスマホの見た目のまま中央の列(幅480px)に寄せ、外側は紙の地(ログイン前の画面・タブレットの幅) |
| 1024px以上・ログイン後 | 左のナビ(256px)+中央の列(本文の幅688px=640px+左右24px) |
| 1024px以上・ようこそ | PCの2列(左に半円と縦書き・右に説明と導線) |
| 1280px以上 | 「預けている」の右に提案の部屋(520px)。チャットの左につながりの一覧(400px) |

821pxは試作の外枠(shell.css)が端末の枠を外す820pxの次とした。区切りの値は `apps/web/src/desktop/media.ts` と `desktop.css` の `@media` で同じにする。

## 2. 作り

- **外枠(`apps/web/src/desktop/DesktopFrame.tsx`)**: ルートの全画面を包むレイアウトのルート(`router.tsx` の `appRoutes`)。幅を `matchMedia` で読み、左のナビ・つながりの一覧・中央の列(`Outlet`)・右の部屋を並べる。中央の列は常に同じ位置に置き、幅が変わっても画面の状態(書きかけの文など)を保つ
- **中央の列**: 画面(`.screen`)は列の幅いっぱいに地と紙の質感を敷き、中身だけを `padding-inline` で列の中央に寄せる。列ごとに `contain: layout` を与え、トースト(`position: fixed`)とシートを列の中に収める
- **各画面への受け渡し(`apps/web/src/desktop/context.ts`)**: 外枠は「左のナビを出しているか」「ようこそをPCの2列で描くか」「右の部屋に出している提案」を各画面へ渡す。外枠の外(単体試験で画面だけを描くとき)では既定値=すべて偽で、スマホの見た目のまま描く
- **左のナビ(`DeskNav.tsx`)**: 試作どおり、ロゴ/[ひとこと置く]/預けている/つながり/アプリ内通知(画面名「お知らせ」・未読の点・ラベルは右上のベルと同じ)/下に自分(表示名と「自分・設定」)。左のナビを出している間は、スマホの下部タブ(`TabBar`)と右上の入口(`TopbarActions`)を描かず、中央の列の上部バーのロゴは見せない
- **左のナビを出さない画面**: ようこそ・はじめる流れ(intro・サインイン・登録・同意)。規約・プライバシー・ヘルプは、ログイン後に「自分」から開いたときは左のナビを出す
- **右の提案の部屋(`HomeRoom.tsx`)**: 「預けている」で、進行中の提案(未回答を先に・無ければ相手の回答待ち)の1件を提案画面(`LatchScreen` に `latchId` を渡す)ごと描き、部屋の中で参加する・今回は見送る・取り消しができる。到着カードは矢印の代わりに「右に表示中」を出す。部屋で成立まで見届けた提案は、一覧から外れても部屋を開いている間は出し続ける。提案が無いときは部屋を消灯して残す(提案が届いても配置が動かず、灯りだけがともる)。部屋の中では「閉じる」は使わない(見せない)
- **チャット**: 1280px以上では左につながりの一覧(`Connections`)を並べ、会話は中央の列に出す
- **ようこそ(`Welcome.tsx`)**: 1024px以上ではPCの2列で描く(左: 半円・縦書き「繋がりたいことを、置いておけばいい。」・「置く · 待つ · 届く」/右: 「ようこそ」「探さなくていい。」・説明・置く/待つ/届くの3段・[はじめる]・[アカウントをお持ちの方]・規約・プライバシー・ヘルプへの導線)

## 4. 試験

- 単体試験(vitest・happy-dom)は画面の大きさをiPhone(390×844)にそろえる(`apps/web/src/test/setup.ts`)。happy-domの既定の幅(1024px)はPC向けの外枠の幅に当たるため
- web E2Eの既定の大きさもiPhone(390×844)にそろえる(`apps/web/playwright.config.ts`)。各specはスマホの画面を前提に書いている
- PCの幅は `apps/web/e2e/desktop-layout.spec.ts`(1280×800・site 52・53)の4本で確かめる(docs/10 §4)
