## 1. 前提

- UIの正本は`prototype/`(オーナー作成済み・完了)。F2'はF2のAPIが揃えば着手できる(バックエンドとフロント基盤の先行は従前どおり)
- LLMは stub → real の順(stubで全工程を通し、realはゲート合格後に接続)。EmbeddingはF3でreal実装済み。Parser/Jevのreal接続と精度ゲートはF9前の独立工程で行う(§2の決定記録)
- 毎コミットの規律: Biome・tsc・vitest(単体+統合)。ゲート通過時にE2Eを追加する

**決定記録(2026-10-20・プロダクトオーナー)**

1. 決定内容: F4(Jevと提案)をF4a(1対1の提案〜成立: Jevの差し替え口とstub・Layer 5・提案化・通知上限と保留・回答・双方YES成立・期限切れ・機会の排他・再提案)・F4b(グループLATCH: Pool最大15・集合選択・1対1最低4回保証の配分)・F4c(提案〜成立の画面: `prototype/`基準)に3分割し、各単位で設計→計画→実装を1周する。F4bとF4cはF4a完了後に着手する。あわせて、Parser/Jevのreal接続実装と精度ゲート(07 §6・09 §4)をF4から外し、F9の前の独立工程へ移す
2. 根拠: F4は1対1・グループ・画面の3領域にまたがり、グループと画面はいずれも1対1の提案〜成立の上に載るため、1対1を先に完成させてから分けて進める方が設計と検証の単位を小さく保てる。real化については、F5〜F8のゲートはstub(Jev=0.9・10 §3)で証明でき、realが必須となるのは公開チェックリスト(11 §1)とstagingのreal疎通(11 §2)である。差し替え口を「1ペア→7軸の数値または失敗種別」の最小形とし、切替・停止・予算計上を共通部に置いたため(07 §5)、後から接続しても修正は接続実装に閉じる
3. 影響: F4のゲート(#12・#14・#15・#17〜#20・#23〜#24)は上表の内訳のとおりF4a・F4b・F4cで分担して証明する(#1〜#35が各フェーズに丁度1回現れる規律は保つ)。F4aは完了した(#12・#14・#15・#18〜#20・#23と#17のAPI部分をworker E2Eで証明)。F4bは完了した(#24をworker E2E(group-latches.spec.ts: 3人のつながり集合と4人の機会集合の全員YESによる成立、1人のdeferと回答期限切れによるクローズとペア別の履歴記録)で証明)。F4cは完了した(#17のUI 2択をweb E2E(latch-flow.spec.ts: 2人の参加による成立と待っていた側の切り替え、見送りと相手側の不成立)で証明)。F8の負荷試験(#33)で初期判定10秒をreal遅延で測る場合は、その時点でreal接続が必要になる

**決定記録(2026-10-20・プロダクトオーナー・F4aの仕上げ)**

詳細(決定内容/根拠/影響)は01冒頭の決定記録に置く。本書の工程に関わる要点のみ記す。

1. 未提示・システムの都合で閉じた提案は提案履歴を消費しない(05 §2.2・06 §4)。F4aの中で実装済み
2. active Intentの意味フィールドの更新で30分の再評価抑制を解除する(05 §3.3・06 §3)。F4aの中で実装済み
3. 地域名をEmbedding入力に含めるかは、F4ではなくLLM real接続(F9前の独立工程・上表)で扱う(07 §4)

**決定記録(2026-10-20・プロダクトオーナー・グループLATCH)**

詳細(決定内容/根拠/影響)は01冒頭の決定記録に置く。本書の工程に関わる要点のみ記す。

1. グループ提案がdefer / noで閉じたときは、閉じた本人を含むペアだけを提案履歴に記録する(05 §2.2・06 §4)。F4bの中で実装済み
2. グループ提案が回答期限切れで閉じたときは、有効なyesを持たない参加者を含むペアだけをexpiredで記録する(05 §2.2・06 §4)。F4bの中で実装済み
3. 成立後の参加取り消し(leave)は本人だけを外して続け、残りが必要人数の下限を割ったときにLATCH全体をcancelledとする(05 §3.3)。F4bの中で実装済み(latch_members.left_atのマイグレーションは戻す手順と対・§4)

## 3. 依存と並行

- F2'はF2のAPIが揃った段階から並行(`prototype/`基準で詳細UIを実装)
- F4bとF4cはF4aの完了後に着手する(F4aの提案〜成立の上に載る)
- F5はF4のあとに必ず(提案の排他・復帰は成立ロジックの上に載る)
- F6はF4と並行可(チャットはmatchedのあとだけ動く)
- LLM real接続はF9の前に完了させる(F8の負荷試験をreal遅延で測る場合はF8の前)
- F9・F10は直列(品質が緑になって初めて公開準備)

## 4. 工程の規律

1. ゲートは02の対応表番号で証明する(自己申告の「だいたいできた」は使わない)
2. マイグレーションは「戻すマイグレーション」と対で作る(11 §3)
3. F3以降、06の観測項目(§7)を最初から計測に入れる(後付けの計測は値が取れない)
4. 未決事項は着手前に扱いを確定する。確定が運用データ前提のIDは暫定案での着手を可とする(例: F3はD-C-01の暫定案で着手し、運用データ後に調整する)
