## 1. 前提

- 03(UX仕様)はプロトタイプの配置(オーナー手配)を待つ。**フロントエンドの画面実装(F2')は03を待つ**が、バックエンド(F0〜F7)とフロント基盤(ビルド・PWA設定)は先行できる
- LLMは stub → real の順(stubで全工程を通し、realはゲート合格後に接続)
- 毎コミットの規律: Biome・tsc・vitest(単体+統合)。ゲート通過時にE2Eを追加する

## 3. 依存と並行

- F2'はF2のAPIが揃った段階から並行(03の配置後、詳細UIを実装)
- F5はF4のあとに必ず(提案の排他・復帰は成立ロジックの上に載る)
- F6はF4と並行可(チャットはmatchedのあとだけ動く)
- F9・F10は直列(品質が緑になって初めて公開準備)

## 4. 工程の規律

1. ゲートは02の対応表番号で証明する(自己申告の「だいたいできた」は使わない)
2. マイグレーションは「戻すマイグレーション」と対で作る(11 §3)
3. F3以降、06の観測項目(§7)を最初から計測に入れる(後付けの計測は値が取れない)
4. 未決事項は各文書の該当IDを解消してから着手する(例: F3の実装前にD-C-01の見直しは不要・暫定案で着手して運用データで調整)
