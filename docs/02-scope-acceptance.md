## 1. 本書の目的と位置づけ

本書は段階リリースを行わない(01決定記録5)ため、対象を**v1.0完成条件(01第25節)**の対応付けとする。すなわち、01第25節のチェックリストが「本当に完成したと言える」ことを、外部から観測できる操作と証拠で示すことが本書の仕事である。また、01第7節の機能範囲を、実装計画の単位として扱える粒度まで具体化する。

## 2. v1.0スコープの確定

01第7節を出発点とした最終境界を次に示す。

**作る(v1.0)**

- アカウント / プロフィール(Google・Appleのソーシャルログイン。プロフィール範囲はD-07)
- 自然言語Intent入力と構造化(両形式のform判定を含む)
- 下書き保存(status=draftでサーバー保存、再開して「預ける」経路)
- Active Intent管理(一時停止・再開・削除・期限管理)
- 5層パイプライン(Hard Filter / Candidate Retrieval / Cheap Judge / Jev / LATCH Engine)
- 1対1 LATCH、および最大4人のグループLATCH
- YES / NO回答と双方承認
- つながりIntentの複数成立(成立後のactive復帰)
- 通知(Web Push+アプリ内) / LATCH成立後チャット(テキストのみ・D-06) / 期限管理
- 成立済みつながり・機会の一覧とチャット履歴の閲覧(D-08)
- ブロック / 通報
- 年齢制限(18歳以上登録、飲酒を含む機会Intentは20歳未満作成不可)
- Analytics(形式別のMutual Latch Rate・つながり品質を含む)
- ユーザーあたりのIntent作成数・更新頻度の上限
- 体感アンケート(完成条件の必須項目からは外す。D-09)
- PWA(ホーム画面追加・Web Push・最小限のオフライン表示)

**設計に含めるが、v1.0では出さない**

- ネイティブアプリ(iOS/Android)— 着手基準は01 D-05
- 供給側Intent(店・施設)— Userのactor_type拡張点として設計にのみ組み込む

**製品として行わない**

- 検索・一覧・ハッシュタグ・トレンド・おすすめフィード等、「探す・見る」機能の一切(01原則9)
- LATCH成立前のメッセージ送信
- チャットの画像・スタンプ・絵文字リアクション・通話(D-06)
- 決済、店舗予約、自動購入、外部在庫連携、広告
- 転職・売買・交際等の規制領域(01第6節・利用規約で禁止)
- 友人関係グラフ(friendships)
- ミュート等のコンテンツ制御機能(notification_level=mutedによる通知抑制設定とは別物)、スパム自動検知、不適切コンテンツ自動検知、なりすまし対策(通報による手動対応で代替)
- 性別の収集・表示(01第22節)
- 自前でのパスワード認証

**境界の運用** — 上記のどちらにも読める機能提案が出た場合は、01第25節の完成条件を満たす最小構成を実装側とし、残りを「行わない」へ置く。判定が割れる場合はプロダクトオーナーの裁可による。

## 3. スコープに関わる決定(D-06〜D-09)

### D-06 チャット機能の範囲

- 決定内容: v1.0のチャットはテキストメッセージのみとする。画像・スタンプ・絵文字リアクション・音声/ビデオ通話は含めない
- 根拠: 成立後の初回接触にはテキストで十分である。画像等のコンテンツは、自動検知を持たない本サービスの安全設計(01第22節)では不適切コンテンツの検知不能な経路になる。テキストのみに絞ることで、通報・ブロックによる手動対応の範囲を文章に限定できる
- 01への影響: 第7節「実装する」のチャット表記に反映(済み)

### D-07 プロフィールの範囲

- 決定内容: プロフィールは表示名(必須)・ひとこと(任意・最大200字)・アイコン画像(任意・未設定は既定アバター)の3項目とする。性別・年齢(表示用)・所在地(表示用)・SNSアカウント連携は持たない。生年月日は年齢検証専用の非公開項目とする
- 根拠: プロフィールは「探して見る」対象ではなく、LATCH成立後の相手確認用の最小情報である(原則9・表示最小化)。性別を保持しないことは出会い系サイト規制法への非該当維持(01第22節)にも直結する
- 01への影響: 第17節Userの補記に反映(後続の05でスキーマ化)

### D-08 つながりLATCH完了後のデータの扱い

- 決定内容: つながりLATCHはcompleted(チャット非活動90日)遷移後も、チャット履歴を読み取り専用で閲覧できる。ユーザーは自分のLATCH(つながり・機会の別を問わず)を一覧から削除でき、削除すると自分の側の表示から消える(相手側の表示は残る)
- 根拠: つながりは静穏になっても振り返る価値がある。削除の伝播を相手側に及ぼすとブロック・通報と絡めた複雑な状態管理を生むため、表示の削除は自分の側に限る
- 01への影響: 第8節に completed 後の閲覧規定を追記(05へ反映。画面表示は`prototype/`基準)

### D-09 体感アンケートの位置づけ

- 決定内容: 体感アンケート(オンボーディング直後・継続利用後)はv1.0機能に含めるが、第25節の完成条件(公開を阻害する必須項目)からは外す
- 根拠: アンケートは製品の前提(01第4節)を確認する計測装置であり、公開の可否を左右する機能ではない。計測装置の不備で公開を遅らせる利益がない
- 01への影響: 第7節の表記に反映(済み)
