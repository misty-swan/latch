## 1. 公開の前提条件(すべて満たすまで公開しない)

- [ ] 02の完成条件#1〜#35がすべてグリーン(特に#34社内クローズドテスト・#33負荷試験)
- [ ] 08 §10の法務確認チェックリストが完了(弁護士等の確認記録を残す)
- [ ] 利用規約・プライバシーポリシーを公開面に配置(規制領域禁止・外部送信の明示・同意導線)
- [ ] LLM精度ゲート(09 §4)合格のうえrealモード固定
- [ ] コストアラートの設定と通知先の確認(04 D-A-04)
- [ ] ロールバック手順(§3)を一度リハーサル済み
- [ ] prodシークレットにテスト鍵が残っていない(起動ガード確認)

## 2. 公開手順

1. GitHub Actionsの手動トリガー(workflow_dispatch)でprodデプロイ(wrangler deploy)
2. DNS(カスタムドメイン)の向き先確認
3. スモーク確認: 新規登録→Intent作成→(スタブ評価ではなく)real評価の疎通→提案とチャットの動作
4. Analytics Engine・Workers Logsに計測が出ていることを確認
5. 初期ユーザー獲得施策(§5)を公開と同時に実行

## 3. ロールバック

- **コード**: `wrangler rollback`(直前バージョンへ即時)。D1スキーマの後方互換性を保つため、マイグレーションは「元に戻すマイグレーション」を必ず対で作成する
- **データ**: D1のポイントインタイムリストア(7日)・VectorizeはD1から再構築(04 §7)
- 判断基準: (a)登録・Intent作成の主要動線が全断、(b)データの欠損・不正表示、(c)プライバシーに関わる事故。軽微な不具合はホットフィックスで対応しロールバックしない

## 4. 公開後の監視

- 最初の72時間: 09 §6の警報線を時間単位で点検
- 以降: 日次点検(MLR・YES率・通報・DLQ・コスト)
- 週次: KPI4群(09 §2)の形式別集計を確認し、ベースライン期間(4週)の記録に充てる

## 5. 初期ユーザー獲得施策(01 D-02・オーナー確定待ち)

段階リリースを行わないため、**公開日から提案が発生する密度**が必要になる(つながりIntentは全国プールで成立する前提6が頼り)。候補施策(案・オーナーが取捨選択する):

1. X等での発信: 「#繋がりたい を探す時代は終わり」系のコンセプト訴求+初期ユーザーの意思例の紹介
2. 種まき投稿: 運営・オーナー自身が多様なジャンルのつながりIntentを実際に預け、提案が成立する様子を見せる(デモではない実運用)
3. コミュニティ接点: 趣味・学びの既存コミュニティへの紹介(宣伝ではなく「意思を置いておける場所」として)
4. 公開時の初期Intent密度の目安: 公開1週間でつながりIntent 200件・ユーザー100人(案・仮置き。前提6の初回判定材料にする)
