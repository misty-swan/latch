## 3. ロールバック

- **コード**: `wrangler rollback`(直前バージョンへ即時)。D1スキーマの後方互換性を保つため、マイグレーションは「元に戻すマイグレーション」を必ず対で作成する。戻す手順は`apps/worker/migrations_rollback/`に置き(自動適用の対象外・`wrangler d1 execute --file`で明示実行する)、新しい番号から順に戻す。マイグレーション0005(チャット・F6a: latch_members.hidden_at・messages.client_idとUNIQUE(latch_id, user_id, client_id))の戻す手順は0005_rollbackで、戻すとLATCHを表示から消した印と再送の重複防止が失われ、表示から消したLATCHが一覧に再び現れる(05 §2.2)
- **データ**: D1のポイントインタイムリストア(7日)・VectorizeはD1から再構築(04 §7)
- **stagingでの予行(F8b)**: stagingの戻し方(`wrangler rollback --env staging`で直前の版へ戻す・D1は戻す手順を新しい番号から`wrangler d1 execute --env staging --remote --file`で明示実行する)は`docs/runbooks/staging.md` §6に置く。2026-10-22にstagingで、Workerを前の版へ戻す→疎通確認→もう一度デプロイして最新へ戻す流れを1回試した。§1のリハーサル(本番を想定した一通り)はF10で行い、台本を`docs/runbooks/rollback-rehearsal.md`に置く(LAT-88)。戻す手順を実行した後に同じ番号のマイグレーションを適用し直す手順(wranglerは`d1_migrations`表のファイル名の行だけで適用済みかを判断し、戻す手順はその行を消さないため、そのままでは適用し直されない)は、戻す手順のSQLの末尾で同じ番号の行を消し、`wrangler d1 migrations apply`で適用し直す(2026-10-27オーナー決定・LAT-88・手元のD1で確認済み・手順は同書 §4)。マイグレーションの中身に誤りがあったときは適用し直さず、記録を書き戻して直したものを新しい番号で作る。本番で戻すかはオーナーが判断基準(下)で決める
