## 1. 原則

このサービスは「まだ誰にも言っていない意思」を扱う。プライバシーは個別機能の前に置く前提であり、通常のSNSより厳しい線引きを最初から引く(01 §21から不変)。検索・一覧・プロフィール閲覧の機能自体を持たない(原則9)ことが最大の構造的保護である。

## 2. 表示の最小化(開示段階の確定)

| 段階 | 開示するもの | 絶対に開示しないもの |
|---|---|---|
| 提案(成立前) | 「条件が合う候補がある」旨・回答期限・必要人数 | 条件サマリ全般・一致度・表示名・プロフィール・アイコン・座標 |
| 成立(matched)後 | 表示名・アイコン・ひとこと(bio)・条件サマリ(「重なったところ」。表示項目はform別に確定済み・05 §4) | raw_text・生年月日・auth識別子 |
| チャット内 | 本人が自発的に送った内容のみ | — |

visibilityはhidden_until_matchの単値であり、成立前の条件サマリ開示は行わない(01 §21の裁定)。一致度(LATCH Score)はユーザーに表示しない(01 §10の裁定)。成立後の条件サマリ(「重なったところ」)の表示項目は、つながり=主題・預け方・人数・地域、機会=主題・日時・場所・人数・予算に確定した(プロトタイプREADME §7のオーナー裁定(2026-10-19)・05 §4のD-B-03解消)。

## 3. 通知経路の規制

- **Web Pushで送るのは提案(proposed)と成立(matched)の2種のみ。** 本文は汎用文のみ(「提案が届いています。詳細はアプリでご確認ください。」・表示語対照(01 §5)どおり・2026-10-19オーナー裁定)。ロック画面・通知履歴・読み上げというOS経路に、成立前の意思を一切載せない
- 不成立(closed)・Intentの期限切れは**アプリ内通知のみ**とする(無関心だった相手に拒絶的な通知を繰り返し届けない)
- この規制はプッシュ購読の有無と独立に適用する(許可拒否ユーザーが自動的に安全になるねじれを許さない)
- **notification_level=mutedはWeb Pushだけを止める。** mutedのIntentが参加する提案・成立はWeb Pushを送らず、アプリ内通知は作る(2026-10-21オーナー裁定・01冒頭の決定記録(通知のAPI))
- **ペイロードは種別と汎用文だけ(F7b実装確定)。** Web Pushのペイロードは`{type, body}`(成立は「つながりが成立しました。詳細はアプリでご確認ください。」)で、LATCH・Intent・通知のIDも意思の内容も載せない(OS経路に識別子も残さない)。タップでアプリ内通知の一覧を開く(F7cのService Worker)
- **送信先は既知のPushサービスに限る(F7b実装確定)。** 購読の登録時にendpointのホストを許可リスト(`fcm.googleapis.com`・`updates.push.services.mozilla.com`・`*.push.apple.com`・`*.notify.windows.com`)と照合し、一致しない購読は400で拒否する(サーバーが利用者の指定した任意のURLへ送信する経路を塞ぐ・05 §3.3)

## 4. 位置情報

- 相手への表示は**地域名のみ**(市区町村・駅・ランドマーク単位)。座標・距離の数値は非表示
- 内部座標は約1kmグリッドに丸め、その代表点に最も近いgeofeaturesの地名を用いる(05 §2.2)。変換はD1内のデータで完結し、外部サービスへの送信はない
- 地域を添付しないIntentは地名自体を表示しない(全国という事実以外に情報がない)

## 5. 外部送信・同意・契約

| 系統 | 送信先 | 送るもの | 送らないもの |
|---|---|---|---|
| Intent Parser | Anthropic | 対象ユーザーのraw_text(最大300字)のみ | 他ユーザーのデータ・プロフィール・位置 |
| Embedding | (外部送信なし・Workers AI内) | 正規化テキスト(プラットフォーム内) | raw_text |
| Jev | TypeSafe(第一候補)/ Anthropic(フォールバック) | 両Intentの正規化テキストのみ | raw_text・識別子 |
| Web Push送信 | プッシュサービス(ブラウザベンダー) | 購読endpoint・暗号化された汎用文ペイロード(種別と本文のみ) | 意思の内容・個別条件・LATCH・Intent・通知の識別子 |
| IdP認証 | Google・Apple | トークン検証に必要な識別子 | その他のプロフィール情報 |

- 同意文言は07 §8の系統別文言による。**同意を取得したユーザーのみがIntentを作成できる**(同意なしは閲覧・設定のみ可)
- 送信の集計(先・種別・件数)を記録し、開示要求に応えられる状態を保つ。送信先事業者を変更する場合は同意範囲の再確認とプライバシーポリシーの更新を行う
- プロバイダ契約に含める5条件: 入出力の学習利用禁止/保持期間の最小化/サブプロセッサの開示/データ所在地の明示/漏洩時の通知義務。Workers AIについてもCloudflareのデータ取扱規約で学習利用なしであることを確認する

## 6. ログと計測

- 構造化ログのフィールドは**許可リスト方式**(列挙の11項目: intent_id / latch_id / status / version / error_code / 層名 / 件数 / latency / notification_id / http_status / push_result)。raw_text・座標・NG条件・表示名は不許可。後ろの3項目はWeb Pushの結果記録(イベントpush.sent・push.failed・push.flush.failed)のためにF7bで加えた。購読のendpoint・鍵・本文はログに出さない
- Serializer段で強制する(04 §4の規律)。Analytics Engineにも同規則を適用する
- **Analytics Engine・Workers Logsには個人を識別できる値(user_idを含む)を書かない。** 両者はユーザー単位の削除ができないため、識別子を書かないことを設計制約とし、プライバシーポリシーに明記する(保持はCloudflareの既定期間)
- survey_responsesはユーザー単位で保持するが、個別のIntent・提案とは紐付けない(09 §7)

## 7. 削除・退会・匿名化

05 §2.5の表が実装の正本である。匿名化の粒度は、時刻系の日単位丸め・proposal条件の時間帯ビン化・地域の市区町村単位化・母集団が小さい期間の月次バッチ生成、を適用する(小規模運用でも再識別の経路を閉じる)。calibration_recordsは匿名化時にlatch_idをnull化し、anonymized=trueの統計値のみ長期保持する。削除・退会はバックアップ(D1のポイントインタイムリストア・最大7日)には遡及しない(保持期間7日である旨をプライバシーポリシーに明記する)。

## 8. 安全機構

**年齢。** 登録18歳以上(birth_date自己申告・IdPから取得しない)。飲酒を含む機会Intentは20歳未満作成不可・20歳以上同士のみ候補化。**満20歳の基準はIntent作成時と候補化時(Layer 1)の双方**とする(19歳での作成が20歳到達後に候補化されることはない)。作成時の判定は有効化の時点(activeでの作成・draftからのactive化)で行い、満20歳未満は422 ALCOHOL_RESTRICTEDとする(draftの保存は検証しない・01 §9。満年齢は日本標準時の誕生日で1つ進む・F7a実装確定)。本人のusers行が無い・activeでないときは年齢を確かめられないため、飲酒を含む機会Intentの有効化を同じ422で拒否する(安全側に倒す。文書の裁量で確定した技術的事項・05 §3.3)。alcohol_involved検出のrecall 100%を精度ゲート(07 §6)で強制する。

**ブロック。** 成立後のLATCH(matched・completed・成立後のcancelled)を共にした相手に対して、いつでも可能(成立前は相手が見えないため対象にならない・05 §3.3)。即時に(a)2人を含む進行中の提案(グループの提案を含む)をcancelledで閉じ(システムの都合の取り消しとして提案履歴を消費しない・05 §2.2)、(b)2人がともに参加を続けるmatchedのLATCHから、ブロックした本人が参加取り消し(leave)と同じ処理で抜け、(c)以降の候補化をLayer 1で恒久除外し、提案直前にも照合する(06 §3)。(b)は1対1ではLATCH全体をcancelledにしてチャットを双方読み取り専用にし、グループでは本人だけが抜ける(残りが必要人数の下限を割ればLATCH全体をcancelled。ブロックされた人を外すことはしない)。ブロックされた側も取り消し済みLATCHの参加者として読み取り専用の履歴を読め、参加取り消しと区別できない「このつながりは終了しました」だけが見える(01 §10。2026-10-21オーナー裁定・01冒頭の決定記録(安全のAPI)。従来の「ブロックされた側は当該LATCHのメッセージを取得できない」は撤回した)。ブロックされた側へブロックを知らせるアプリ内通知は作らない(提示済みの提案が閉じたときのclosedは通常の不成立と区別せずに届く)。completed・成立後のcancelledのLATCHは変えない。解除は任意(候補化は再開するが、提案履歴による同一ペア排除と、ブロックで終わったLATCHは戻さない)。

**通報。** 提案・成立の各状態から通報でき、対象(ラジオ)と理由(スパム/嫌がらせ/不適切/その他)を選ぶ。提案段階の導線は提案画面右上の「…」→「この提案を通報する」とする(2026-10-19オーナー裁定・F7で実装)。成立後はプロフィール・アイコン・メッセージも通報対象とする。提案段階の通報は、成立前は相手が見えないため本人に対象者を選ばせず、自分以外の全参加者を対象者として1人1行で記録する(通報しても提案は閉じない・2026-10-21オーナー裁定・01冒頭の決定記録(安全のAPI))。成立後の通報は対象者(メッセージは対象の発言)を指定する(05 §3.3)。成立後の参加者だった人は、ブロックや参加取り消しでLATCHから抜けた後も通報できる(2026-10-21オーナー裁定・01冒頭の決定記録(安全のAPI)の4)。任意の補足(note)は500字までとする。受付のみを行い、対応は手動(自動検知は行わない・02 §2)。運用規定: 受付から5営業日以内に確認し対応をreports.statusへ記録する/同一対象への重複通報は統合する(同じ通報者が同じLATCH・対象者・対象(メッセージは同じ発言)を未対応のうちに再び通報したときは1件にまとめて理由・補足・時刻を今回の値に置き換える・F7a実装確定。通報者をまたぐ統合は運用で行う)/**通報の存在・内容は被通報者へ通知しない(報復防止)**/虚偽通報の反復は規約違反とする。open通報の滞留(7日超)は警報線(09 §6)で監視する。

**営業・勧誘への構造的耐性。** 検索不可・成立前の情報非開示・相互YES必須・通知上限(日6)・Active Intent上限(5)の組み合わせで、「意思を置いて待つ」以外の接近経路を存在させない。規約で営業目的の使用を禁止し、通報の対象とする。

**レート制限。** 1ユーザーあたり60req/分・Active Intent 5件/ユーザー・作成20件/日・更新6回/時間(04 §5・bindingとusage_countersで実装)。

## 9. 出会い系サイト規制法への非該当を維持する設計

1. 異性交際の機会の提供を事業目的としない(サービスの目的はジャンルを問わない趣味・目的のつながり)
2. 性別を収集・判定・表示に使わない(usersに性別カラムなし・05 §2.2)。v1.0で性別の登録項目を持たない(01 §22確定)
3. 利用規約で交際・出会い目的の使用を禁止する
4. 将来の課金は機能課金(通知枠・上限緩和)のみとし、性別・交際目的に依存する課金を行わない

## 11. セキュリティ

- JWT(1時間)+回転式リフレッシュ(30日)・失効はKV(jti)。prodでテスト鍵が残存する場合の起動ガード(04 §4)
- Web PushのVAPID鍵(VAPID_PUBLIC_KEY・VAPID_PRIVATE_KEY・VAPID_SUBJECT)はWorkers Secretsで管理する。prodでLATCH_PUSH_MODEがreal以外・VAPID鍵のいずれかが無い・コミット済みのテスト用VAPID鍵が設定されている場合は起動を拒否する(04 §4・F7b実装確定)。本番鍵の発行と登録はF10(公開準備)で行う
- WebSocketは**60秒・jose署名のチケット**で認証(05 §3.4)。チケットは接続URLのクエリで渡す(ブラウザのWebSocketはAuthorizationヘッダを送れないため)。署名・期限・用途(typ)・LATCH IDの一致の検証と、本人がそのLATCHの参加者でありmatchedであることのD1での再検証は、接続ごとにWorkerのルートで行う。チケットは**1回限り**とし、DOが使用済みのjtiを記録して再使用を拒否する(04 §4)。いずれの失敗も401とし、理由を区別しない(F6a実装確定)
- チケットはURLに載るため、アプリのログに書かない(アプリはURLをログに出さない・ログは許可リスト方式・§6)。プラットフォームの要求ログにURLのクエリが残り得るが、接続に使ったチケットは使用済みで、未使用でも発行から60秒で失効するため、影響は限定される
- R2アイコン: 形式(PNG/JPEG/WebP)・サイズ(1MB)をWorkerで検証してから保存。コンテンツ種別を固定して配信
- セキュリティヘッダ(X-Content-Type-Options・Referrer-Policy・CSP)はAssets配信に適用
- シークレットはWorkers Secretsのみに保存し、リポジトリにコミットしない(テスト用IdP鍵はstaging専用・04 §6)
