# LATCH UIプロトタイプ — 「空押し(からおし)」

> 探さなくていい。繋がりたいことを、置いておけばいい。

このフォルダは、LATCHの画面デザインと、それを実際に触れる試作品(プロトタイプ)です。UX仕様書(03)を書くときの「実装基準」として使える粒度で作っています。

成果物は次の2つです。

| 成果物 | 中身 | 開き方 |
|---|---|---|
| **① 試作品** | 実際にタップして流れと動きを確かめられるWebページ | `prototype/index.html` をブラウザで開く(ダブルクリックでよい) |
| **② デザインキャンバス** | 全64枚のボード(画面・空状態・エラー・夜・デスクトップ・デザインシステム) | https://claude.ai/artifact/NvRViFRxm84znHifMyqM3j |

キャンバスは非公開です。ほかの人に見せるときは、キャンバス画面の「共有」メニューから共有してください(共有するまでは本人以外は開けません)。

## 1. 試作品の使い方

1. `index.html` を開くと、中央にスマートフォン、右に「プロトタイプの操作」パネルが出ます
2. 画面はそのまま触れます(文字入力・ボタン・タブなど)
3. 相手の動きなど、ひとりでは起こせない出来事はパネルの「出来事を起こす」から起こします
   - 例: 「提案を届ける」→ ホームに提案が届く →「参加する」→ パネルの「相手も参加する」→ 成立の演出(かちっ→墨がにじむ)→ チャット
4. 「画面へ移動」から、全画面・全状態(空・エラー含む)へ直接飛べます
5. 「表示」で昼/夜、「通知」で通知の許可状態、「接続」でオフラインを切り替えられます
6. スマートフォンで開いた場合、パネルは画面右端の「デモ操作」タブから引き出します

補足
- データはすべてこの端末の中だけの作りものです(外部への送信はありません)。「最初からやり直す」で初期状態に戻ります
- 物語の中の「いま」は 2026年10月16日(金)18:20 に固定しています(「今夜20時」の例が自然に読めるようにするため)
- 書体はインターネット接続時にGoogle Fontsから読み込みます。オフラインでは端末の日本語フォントで表示されます
- 開発者向け: URLの末尾で画面を直接指定できます(例: `index.html#/proposal/p1`、撮影用に動きを止める `index.html?shot#/home`)

## 3. デザインの考え方

空押しは、インクを使わずに紙を押し、形だけを浮かび上がらせる印刷の技法です。LATCHではこれを「成立前は相手が見えない」という約束の表現に使います。

| 要素 | 意味 | 画面での現れ方 |
|---|---|---|
| 墨 | 自分のもの | 自分の言葉・自分の半円は、はっきり刷る |
| 空押し | まだ見えない相手 | 形はあるのに色がない半円(=白い待ち時間) |
| 灯り(琥珀) | 提案が届いた | 二つの半円の隙間から灯りが漏れる。届いたときにしか使わない色 |
| かちっ | お互いが参加した | 0.3秒で噛み合い、相手の色が墨のようににじんで現れる |

- **動き**: ふだんは遅く、ほとんど気づかないくらい(呼吸6.4秒・灯り4.8秒)。成立の瞬間だけ速く、はっきり。「ゆっくり、そして一度だけ、かちっ」
- **見送り**: 半円が回転して棚に横たわり、「そっと、棚に戻しました。」。拒絶の言葉は使わない
- **提案画面**: 照明を落とした「部屋」(夜の配色)に、灯りだけが漏れる。表示は「候補がある」「回答期限」「必要人数」の3つだけ
- **書体**: 明朝(Shippori Mincho)=人の声、ゴシック(Zen Kaku Gothic New)=アプリの声、等幅(DM Mono)=時間と数字
- **縦書き**: 「ようこそ」「預けました」「棚に戻しました」の3つの瞬間だけに使う
- **夜**: 紙と墨の明暗を入れ替える。墨は月明かりの白になり、深夜でも目に刺さらない

## 4. デザインシステムの要点(実装で再現するための値)

### 色(すべて文字は背景に対して4.5:1以上)

| 役割 | トークン | 昼 | 夜 |
|---|---|---|---|
| 紙(地) | `--paper` | `#EEF0F2` | `#0F1420` |
| 面(入力欄・シート) | `--surface` | `#F8F9FA` | `#161D2B` |
| 墨(本文・自分の半円) | `--ink` | `#1A2030`(14.2:1) | `#E6EAF0`(15.2:1) |
| 墨・補(説明) | `--ink-2` | `#4A5366`(6.8:1) | `#A8B0BF`(8.4:1) |
| 墨・注(注記・時間) | `--ink-3` | `#5F677A`(5.0:1) | `#8790A1`(5.7:1) |
| 罫 | `--line` | `#D6DBE2` | `#252E40` |
| 灯り | `--lamp` | `#E9A23B` | `#F0B24E` |
| 灯りの文字 | `--lamp-ink` | `#8A5200`(5.6:1) | `#F3BE66`(10.8:1) |
| 注意(退会・ブロックのみ) | `--danger` | `#A33A30`(5.7:1) | `#EF8F86`(7.8:1) |

切り替えは要素の `data-theme="light"` / `"dark"`。設定画面では「端末の設定に合わせる/昼/夜」を選べます。

### 書体と大きさ

| 役割 | クラス | 書体・大きさ |
|---|---|---|
| 大見出し | `.t-display` | 明朝 30 / 行間1.5(大36・小24) |
| 人の言葉 | `.t-words` | 明朝 16 / 1.85 |
| 見出し | `.t-title` / `.t-head` | ゴシック 20・16 |
| 本文 | `.t-body` | ゴシック 15 / 1.8 |
| 注記・ラベル | `.t-caption` / `.t-label` | ゴシック 13 |
| 時間・数 | `.t-meta` | 等幅 12 |

見出しは文節で改行(`word-break: auto-phrase`)、約物を詰める(`palt`)。

### 寸法と動き

- 左右の余白24px・押せるものは高さ44px以上・主ボタン高さ56px(丸い帯)
- 半円の状態クラス: `.latch` に `.is-empty / .is-draft / .is-waiting / .is-arrived / .is-pressed / .is-latched / .is-ended`、見送りは `.dome-rest`
- 動き: 呼吸 6.4s ease-in-out / 置く 1.0s `cubic-bezier(.16,1,.3,1)` / 寄せる 0.72s 同 / かちっ 0.3s `cubic-bezier(.34,1.56,.64,1)` / にじむ 1.5s `cubic-bezier(.3,.6,.35,1)` / 棚に戻す 0.76s `cubic-bezier(.65,0,.35,1)` / 画面のつなぎ 0.42s
- 端末で「視差効果を減らす」が有効なら、すべての動きを瞬時の切り替えにする(`prefers-reduced-motion`)

## 6. 仕様上の約束をどう守ったか

- 提案に出すのは「条件が合う候補があります」「回答期限」「必要人数(グループのみ)」だけ。一致度・名前・アイコン・プロフィール・主題は出さない
- 回答は「参加する / 今回は見送る」の2択だけ(右上の「…」は通報用で、回答の3択目ではない)
- 参加後は「相手の回答を待っています」と回答期限だけを表示し、催促しない。回答の取り消しは1操作
- 見送り後の説明は1回だけ: つながりは「この相手との提案は今後届きません。」、機会は「条件が変われば、また届くことがあります。」
- 相手の離脱・ブロック・退会は区別せず「このつながりは終了しました」だけ
- 状態の呼び名は仕様の9つ(下書き/預けている/一時停止中/期限切れ/取り下げ/回答を待っています/相手の回答待ち/つながった/終了)
- プッシュ通知は提案と成立の2種だけで、本文は汎用文。不成立・期限切れはアプリ内通知(画面名「お知らせ」)だけ
- 入力の主役は便箋のようなテキスト欄と300字のカウンター。フォーム入力は「自分で入力する」の逃げ道だけ
- 検索・一覧・トレンド・おすすめの画面は無い。アプリの画面の言葉に「探す」は使っていない(機械的に確認済み)
- チャットはテキストのみ(画像・スタンプのボタンを置かない)

## 7. オーナーに確認してほしいこと(仕様書どうしの食い違い・決めごと)

制作中に、仕様書どうしで食い違っている点や、03(UX仕様)で決める必要がある点が見つかりました。試作品では下記の「試作品での扱い」で作っています。

| # | 内容 | 試作品での扱い |
|---|---|---|
| 1 | 09 §7 の利用4週後アンケートの設問「探さずに待つ体験で、欲しいつながりは得られましたか?」が、「画面の言葉に『探す』を使わない」方針と食い違う | 試作品には未収録。言い換え案:「預けて待つ体験で、欲しいつながりは得られましたか?」 |
| 2 | 05 §2.5 は退会した相手の表示名を「退会したユーザー」とするが、01 §10 は「終了の理由(離脱・ブロック・退会)を区別して見せない」としている。表示名で退会だと分かってしまう | 終了したつながりは原因を問わず「つながっていた相手」と表示する案で作成 |

| 6 | 提案の段階からの通報(08 §8) | 提案画面右上の「…」→「この提案を通報する」 |

## 8. どう自己チェックしたか

- 全画面をブラウザ(Chromium)で実際に表示して撮影し、昼・夜の両方で崩れ・読みにくさを確認して修正
- 動き(預ける・参加する・見送る・成立)は実時間でコマ撮りし、順番と見え方を確認して修正(成立時に合わせ目へ白い筋が出る不具合などを解消)
- 文字色はすべてコントラスト比を計算し、4.5:1以上を確認
- キャンバスの64ファイルは、タグの閉じ忘れ・配置表との対応・表示サイズを機械的に検査

## 9. この試作品に含めていないもの

- デスクトップ表示はキャンバスのデザインのみ(試作品はスマートフォン幅)
- 利用4週後アンケート(上記 #1 の確認後に追加)
