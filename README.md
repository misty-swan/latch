# LATCH

> 探さなくていい。繋がりたいことを、置いておけばいい。

LATCHは、ジャンルを問わない「つながり」のマッチングサービス。「こういう目的で人とつながりたい」という条件付きの意思(Intent)を預けておくと、意味的に成立する相手が現れた瞬間にだけ提案が届き、双方がYESしたときだけつながる。検索も、アピールも、断られることもない。

## 現在の状態

文書策定段階(実装はまだ着手していない)。要件定義(v1.0完成形の定義)とスコープ合意が揃ったところ。段階的な検証リリース(MVP)は行わず、v1.0完成形を作り切ってから公開する。

## リポジトリ構成(計画)

```
latch/
  docs/          # 文書群(正本)
  prototype/     # UI実装基準のプロトタイプ(プロダクトオーナーが手配・配置)
  backend/       # 04(アーキテクチャ)・05(データモデル)策定後に骨組み作成
  frontend/      # 03(UX仕様)=新プロトタイプ確定後に骨組み作成(PWA)
```

各ディレクトリは担当文書の策定時に作成する(空ディレクトリは先に作らない)。

## 旧実装について

旧コンセプト(飲み・食事領域の段階的検証MVP)の実装と文書群は `../latch-legacy` にアーカイブしている(開発の経緯の完全な記録)。設計資産の引き継ぎ範囲は [docs/reviews/d04-reuse-investigation.md](docs/reviews/d04-reuse-investigation.md) が定める。

## 開発

開発着手の前提は docs の整備(03 UX / 04 アーキテクチャ / 05 データモデル)。開発規律(uv・ruff・毎コミットのlint/test・時刻はClock抽象経由)は旧リポジトリと同じものを引き継ぐ。
